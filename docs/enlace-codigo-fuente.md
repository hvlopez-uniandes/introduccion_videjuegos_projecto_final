# Enlace al código fuente actual

Este archivo sustituye o complementa cualquier tabla en el LMS: aquí debe constar **cómo acceder al código fuente** del proyecto en vigor para la fecha de revisión correspondiente.

## Opción recomendada: repositorio Git

| Campo | Valor |
|--------|-------|
| **URL del repositorio** *(página)* | **[github.com/hvlopez-uniandes/introduccion_videjuegos_projecto_final](https://github.com/hvlopez-uniandes/introduccion_videjuegos_projecto_final)** |
| **Clonar vía HTTPS** | `git clone https://github.com/hvlopez-uniandes/introduccion_videjuegos_projecto_final.git` |
| Rama principal | **`main`** |
| Etiqueta / release final *(añadir ante entrega sumativa si el curso lo pide)* | *pendiente* → usar `git tag …` cuando el build coincida con lo publicado en itch.io |

## Opción alternativa: archivo ZIP

Si el curso exige cargar código en un archivo **`.zip`** (por ejemplo porque el LMS no acepta solo enlace público):

| Campo | Valor |
|--------|--------|
| ¿Se sube zip a la plataforma del curso? | **No** *(por defecto: el código está en GitHub público).* |
| Nombre esperado del zip | *Solo si docencia lo exige ej.* `introduccion_videjuegos_projecto_final-AAAA-MM-DD.zip` |
| Observaciones | Generar también con **GitHub → Code → Download ZIP** desde la misma URL si hace falta una copia estática para registro institucional. |

> **Buena práctica:** en todo caso debe existir un **histórico de commits** público antes de la fecha final donde el código refleje el **build publicado** en itch.io (ver rúbrica del curso).
